# 토익 단어 앱 — 설계 문서

## Context

12/13, 12/27 토익에서 800점 이상을 받기 위해, 단어 500개(`toeic-vocab-500.md`)를 52일 동안 3세트씩 겹쳐 가며 외우는 개인용 웹앱을 만든다. 1일차는 2026-10-29(내일)이다. 앱은 설치 없이 폰 브라우저에서 돌아가고, 홈 화면에 추가하면 앱처럼 열리며, 오프라인에서도 동작한다.

**기준 명세는 `toeic-app-prompt.md`이다.** 이 문서는 그 명세를 대체하지 않고, 대화에서 정한 것과 명세에 비어 있던 부분을 채운다. 둘이 다르면 이 문서를 따른다.

## 사용자가 정한 것

- 하루 중 **짬날 때 폰으로 잠깐씩** 연다. 하루치(최대 카드 30장 + 퀴즈 30문제)를 여러 번 나눠서 하는 게 보통일 것이다.
- **타이핑은 하지 않는다.** 학습·퀴즈·오답 복습은 전부 탭이나 스와이프로만 한다.
- GitHub 계정이 있고, 저장소를 공개해도 괜찮다.
- **내일(10/29) 시작은 필수가 아니다.** 명세 순서대로 끝까지 만든 뒤 배포한다. 시작이 늦어지면 설정에서 계획 시작일을 바꾸거나 "하루 여러 학습일"로 따라잡는다.
- **짝꿍 표현 빈칸 문제에는 빈칸 아래에 정답의 한국어 뜻을 힌트로 보여준다.** 짧은 구절에는 자연스러운 답이 여러 개일 수 있기 때문이다(예: "___ 30 minutes"에 approximately와 nearly). 뜻이 겹치는 단어를 보기에서 빼는 규칙(아래 12번)과 함께 쓰면 정답이 하나로 정해진다.

## 목표 / 비목표 / 안티골

- **목표:** 52일 일정을 하루도 건너뛰지 않고 진행하는 것. 짧게 끊어서 써도 진행이 절대 날아가지 않는 것. 엄지 하나로 다 되는 것.
- **비목표:** 서버, 계정, 기기 간 동기화(백업 파일로 대신함). 앱 안에서 단어를 편집하는 기능(md를 고치면 됨). 타이핑으로 답하는 퀴즈. SRS 같은 별도 복습 알고리즘(3세트 슬라이딩만 쓴다). 푸시 알림.
- **안티골(돌아가더라도 실패인 것):**
  - 정답이 두 개로 읽히는 문제
  - 앱이 닫혀서 진행이 사라지는 것
  - 하루 쉬었다고 단어가 건너뛰어지는 것
  - 이동 중에 갑자기 소리가 나는 것
  - 기본 템플릿처럼 보이는 디자인

## 명세 보완 — 제가 정한 것 (검토 부탁)

### 날짜·진도
1. 모든 날짜는 기기 로컬 날짜 `YYYY-MM-DD`로 다룬다. `toISOString()`은 쓰지 않는다. 한국 시간 오전 9시 전에는 날짜가 하루 어긋나기 때문이다.
2. **하루 1학습일 잠금**은 *완료 시각*을 기준으로 한다. 오늘(로컬 날짜) 완료한 학습일이 있으면 다음 학습일은 자정까지 잠긴다.
3. **계획 대비 표시**
   - 오늘의 계획 학습일 = (오늘 − 시작일) + 1이며, 1~52 범위로 자른다.
   - 밀린 일수 = max(0, (오늘의 계획 학습일 − 1) − 완료한 학습일 수).
   - 오늘 분량을 아직 안 한 것은 밀림으로 치지 않는다. 0이면 "계획대로", 그 외에는 "N일 밀림"을 보여준다. 계획보다 앞서도 "계획대로"로 표시한다.
4. **스트릭**은 학습일을 완료한 날짜가 연속된 일수이다. 오늘 아직 안 했으면 어제까지의 스트릭을 그대로 보여준다(끊긴 것으로 보지 않는다). 하루에 여러 학습일을 끝내도 1일로 센다.
5. **학습한 단어 수(진행 링)** = min(완료한 학습일 수, 50) × 10. 단어장에서 흐리게 표시하는 기준도 같다. 진행 중인 학습일의 새 Set는 흐리게 하지 않는다.
6. **소요 시간**은 앱이 화면에 보이는 동안만 잰다(`visibilitychange`). 하루치를 나눠서 하니 시작부터 완료까지의 시계 시간은 의미가 없다.
7. 하루 기록의 날짜와 기록 탭 달력의 표시는 **완료한 날짜**를 기준으로 한다.
8. 52일차를 마친 뒤 홈은 "완주" 상태로 바뀌고 오답노트 퀴즈를 권한다.
9. 시험 D-day 표시는 "D-46"처럼 보여주고, 당일은 "D-Day", 지난 뒤에는 "종료"로 바꾼다.

### 퀴즈
10. **유형 섞기:** 단어마다 가능한 유형 중 하나를 무작위로 고르되, 세 유형이 전체적으로 고르게 섞이게 한다.
11. **빈칸 유형을 쓰는 조건:** 짝꿍 표현 안에 표제어가 그대로 들어 있어야 한다(대소문자 무시, 단어 경계 기준). 또 빈칸을 뺀 나머지에 A/B/~/구두점이 아닌 실제 단어가 하나 이상 있어야 한다. 예를 들어 "However, ~"는 빈칸 유형으로 내지 않고 1·2번 유형으로 낸다.
12. **정답이 두 개가 되지 않게 하기**
    - 뜻이 겹치는 단어는 오답 보기에서 뺀다. 뜻을 쉼표로 나누고 괄호 안 내용과 공백을 정리한 뒤, 하나라도 같으면 뺀다. 예: due to / because of / owing to, confirm / verify, upon / as soon as.
    - 글자는 달라도 사실상 같은 뜻인 쌍(예: although / even though)은 코드 안의 작은 **동의어 그룹 목록**으로 뺀다. 빌더가 500단어를 한 번 훑어 목록을 만들고, md에 없는 단어는 무시한다.
    - 빈칸 유형에는 빈칸 아래 뜻 힌트가 있으므로(사용자 결정), 위의 두 규칙만으로 정답이 하나로 정해진다. 추가로, 후보 단어의 짝꿍 표현에서 그 단어를 빈칸으로 바꾼 결과가 문제와 같으면 보기에서 뺀다(예: attend a meeting / arrange a meeting).
    - 화면에 보이는 뜻(보기와 힌트)은 괄호까지 포함한 원문 그대로 둔다.
13. **오답 보기 풀:** v. / n. / adj. / adv.(접속부사 제외)는 품사별로 따로 둔다. prep. + conj. + phr. + 접속부사(뜻에 "(접속부사)"가 들어 있는 adv.)는 하나의 풀로 묶는다. 같은 풀에서 3개를 못 채우면 다른 품사에서 채운다.
14. **단어별 누적 기록**에는 하루 흐름의 본 퀴즈와 오답 재퀴즈를 모두 센다. "오답만 퀴즈"(자유 연습)는 진도에도 기록에도 영향을 주지 않는다. 오답노트에는 한 번이라도 틀린 단어가 전부 남는다(목록이 줄어들지 않는다).
15. 하루 기록의 "첫 퀴즈 점수"는 본 퀴즈 1회차 점수이다.

### 데이터·오프라인
16. **단어 키는 표제어 소문자**로 한다. md에서 뜻이나 짝꿍 표현을 고쳐도 기록은 남는다. 표제어를 바꾸면 그 단어의 기록은 새로 시작한다. 진행 중인 세션에 md에서 사라진 단어가 있으면 조용히 건너뛴다.
17. **저장:** localStorage에 동작 하나마다(카드 이동, 답 선택) 바로 저장한다. 처음 실행할 때 `navigator.storage.persist()`를 요청한다. 저장 데이터에는 처음부터 스키마 버전을 넣어, 배포 뒤 업데이트에서도 폰에 쌓인 기록을 그대로 옮길 수 있게 한다.
18. **백업:** JSON 파일(스키마 버전, 기록, 설정, 진행 중 세션 포함). 가져오기는 전체를 교체하며 한 번 확인한다. 파일 공유(Web Share)를 지원하면 그걸 쓰고, 아니면 다운로드로 내보낸다(iPhone 대응).
19. **Service worker 캐시**
    - 앱 파일: 버전별 캐시(cache-first)
    - md 파일: network-first, 오프라인이면 캐시를 쓴다. md를 고치면 바로 반영되게 하기 위함이다.
    - 폰트(jsDelivr, Google Fonts): 처음 받을 때 캐시한다(cache-first).
    - 새 버전은 다음 실행 때 적용된다.

### 화면
20. 홈에서 가장 큰 버튼은 "시작/이어하기"이고, 엄지가 닿는 아래쪽에 둔다. 앱을 열고 한 번만 누르면 이어서 할 수 있어야 한다.
21. 단어장은 세트별로 접고 펼치는 목록이 기본이다. 검색창은 위쪽에 두는 선택 기능이다.
22. 소리는 절대 자동으로 나지 않는다. 발음은 버튼을 누를 때만 나온다.

### 배포
23. 저장소는 공개 `toeic-vocab`이고, 주소는 `https://<아이디>.github.io/toeic-vocab/`이다. 이 폴더 자체를 저장소로 쓴다(md가 단일 원본이므로).
24. `gh` CLI가 없으니 winget으로 설치한다(승인 받고). 사용자가 `! gh auth login`으로 브라우저 로그인을 직접 한다. 공개 저장소에 개인 이메일이 드러나지 않도록, 커밋 이메일은 GitHub noreply 주소를 저장소 로컬 설정에만 쓴다.
25. Pages는 main 브랜치 루트에서 빌드 없이 배포한다. `.nojekyll`을 추가한다.
26. 홈 화면 추가 안내에 "iPhone에서는 홈 화면 앱과 Safari 탭의 저장 공간이 따로라서 **항상 홈 화면 아이콘으로 열 것**"을 넣는다.

## 빌더에게 맡기는 것

- 파일과 모듈 구성(단, 파서·일정·퀴즈 생성·날짜 함수는 브라우저와 Node 양쪽에서 import 가능한 순수 ES 모듈로 만든다)
- 구체적인 색상 값. 제약: 강조색은 하나. 정답/오답은 강조색과 확실히 다른 색이어야 하고, 색만으로 구분하지 않고 ✓/✕ 아이콘을 함께 쓴다.
- 애니메이션 세부, 스와이프 임계값, 차트 형태, 아이콘 디자인과 PNG 생성 방법(npm 의존성 없이)

## 참고 사실 (사용자 결정 사항 아님)

계획대로 가면 1차 시험(12/13)이 46일차라서 Set 47–50(보강 40단어)은 1차 시험 전에 처음 보지 못한다. 52일차는 12/19이다. 앞당기고 싶으면 "하루 여러 학습일" 설정으로 할 수 있다.

## 구현 순서 (명세 §7)

1. md 파서와 일정 함수, 그리고 테스트
2. 학습 → 퀴즈 → 오답 복습 흐름, 저장과 이어하기(MVP)
3. 홈 / 기록 / 오답노트 / 단어장 / 설정 화면
4. 디자인 다듬기, 다크 모드, PWA, 오프라인
5. GitHub Pages 배포, URL과 홈 화면 추가 안내

단계마다 한국어로 짧게 보고하고, 결정할 게 생기면 묻는다.

## 검증

- `node --test`(Node v24 내장, 의존성 없음)
  - 파서: 500단어, 50세트. 499개처럼 잘못된 md는 에러를 낸다.
  - 일정: 모든 Set가 정확히 3일 등장한다. 1, 2, 3, 50, 51, 52일차의 Set 목록이 맞다.
  - 퀴즈 생성기: 보기 4개가 서로 다르다. 뜻이 겹치거나 동의어 그룹에 속한 단어가 보기에 섞이지 않는다. 빈칸 유형 조건이 지켜진다.
  - 날짜 함수: 한국 시간 오전 9시 이전 경계에서도 날짜가 맞다.
  - 계획 대비 표시와 스트릭 계산이 맞다.
- 로컬 서버(`python -m http.server`)와 Chrome 자동화로 390px 폭에서 확인
  - 1일차 전체 흐름을 끝까지 진행한다.
  - 퀴즈 도중에 탭을 닫았다가 다시 열면 같은 문제에서 이어진다.
  - 다크 모드, 오프라인 재실행, md 수정이 바로 반영되는지, 에러 화면이 나오는지 확인한다.
- 배포 후 실제 URL에서 manifest와 service worker가 등록되는지, 주요 흐름이 도는지 확인한다.
